# 成员打卡页（网页端）

## 1. 它解决什么

家里有人不用 App —— 可能是手机太老、可能是装不了、也可能只是**不想再学一个新东西**。
App 里点两下能给他发一个链接，他存进微信收藏，每天点开就是今天的清单，
点一下勾就算打了卡，家里人手机上的提醒会同步消失。

```
App（家里人）                       浏览器（成员）
   │                                    │
   │ POST /members/:id/link             │
   │ ─────────────────────────────────► │
   │ ◄── https://host/m/<token> ─────── │
   │                                    │
   │                          打开链接  │
   │                    GET /m/<token>  │
   │                  ├─ 换票、落 Cookie │
   │                  └─ 302 → /m/      │
   │                                    │
   │                    GET /m/         │  静态 HTML
   │         GET /m/api/today           │  JSON（认 Cookie）
   │         POST /m/api/checkin        │  JSON
```

**token 只出现一次。** 换完票就 302 到 `/m/`，地址栏里不再有它 ——
否则用户截图、复制地址、在群里问"你看我这是不是坏了"，token 就一起传出去了。

## 2. 三个关键决策

| 决策 | 选择 | 否决的选项和原因 |
|---|---|---|
| 前端形态 | **单页、无框架、原生 JS** | 引 React/Vue 就要构建步骤，和"服务端零 npm 依赖"的基调冲突；而这个页面只有一屏，状态不超过 5 个 |
| 部署位置 | **和接口同源**（`server/public/`） | 单独站点就要跨域 → Cookie 得 `SameSite=None` → **微信内置浏览器直接丢**。同源之后 `SameSite=Strict` 就能用 |
| 页面逻辑 | **抽成纯函数放 `web/rules/`** | 全塞进 `app.js` 就只能靠手点验证，而"401 该不该重试"是手点不出来的 |

## 3. 路由和静态层怎么共存

服务端有两类东西抢同一个路径空间：**注册过的接口**（`/m/api/*`）和**磁盘上的文件**（`/m/app.js`）。
顺序是：

1. 逐条匹配路由表 → 命中就执行；
2. **一条都没命中**且方法为 `GET`/`HEAD` → 交给静态层；
3. 命中路由但方法不对 → **405**，不进静态层（否则 `/sync` 会被当成"找 sync 这个文件"回 404）；
4. 都没命中 → 404，按 `Accept` 决定回 JSON 还是 HTML。

### 坑：`/m/:token` 会吃掉 `/m/app.js`

`/m/:token` 的正则是 `[^/]+`，`app.js` 完全符合"一段 token"的形状。第一版就是这样：
`/m/` 页面 **200**，但脚本和样式全 **401** —— 表现是"白屏 + 一个空标题"，
从现象根本想不到是路由冲突。

修法有三个候选：

| 方案 | 为什么不用 |
|---|---|
| 给 token 加前缀（`/m/l/<token>`） | 已发出去的链接全废 |
| 静态层优先 | `/m/<token>` 就永远进不去 —— token 也能被当成文件名 |
| **显式名单** | ✅ 采用。`app.js`/`app.css`/`index.html`/`favicon.ico` 不当作 token |

名单里的名字命中后，handler 返回 `STATIC_PASSTHROUGH` 哨兵值，http 层识别到就改走静态层。

> ⚠️ **判定必须是"名单"，不能是"带扩展名"。** token 是 base64url 随机串，
> 完全可能以 `.js` / `.css` 结尾。写成"看扩展名就让路"，会把真链接送去静态层找文件、
> 拿到 404 —— 和"链接已作废"长得一模一样，排查时根本不会怀疑到路由头上。
> `server/test/static.test.mjs` 里有四条专门钉这个的用例。

## 4. 安全边界

| 关口 | 做法 | 防的是什么 |
|---|---|---|
| 鉴权 | Cookie（`HttpOnly` + `SameSite=Strict` + `Secure`）；`?t=` 只在首次兜底 | token 泄露在 Referer / 日志里 |
| 两套凭据隔离 | 网页的 ticket **不能**当 App 的 Bearer 用，反之亦然 | 一条链路出问题不牵出另一条 |
| 静态层 | 扩展名白名单 + `realpath` 前缀比对 + 不列目录 | `../`、符号链接、`.db`/`.env` 被下载 |
| 输出转义 | 所有插入过 `esc()`，`data-*` 上只放 key | 任务名/备注里的 HTML 变 XSS |
| 页面头 | CSP `default-src 'none'`（含 `frame-ancestors 'none'`）+ `nosniff` | 被别人的页面嵌走、内容嗅探 |
| 日志 | pathname 过 `redactRequest` | 成员链接 token 写进日志文件 |

**网页端能做什么，不能做什么：**

| 能做 | 不能做 |
|---|---|
| 看"今天"以及前后几天 | 改任务规则（加/删/暂停任务） |
| 打卡 / 取消 / 补卡（30 天窗口内） | 管理成员、配对设备 |
| 写一段文字备注 | 传照片（照片只存在 App 本地） |
| — | 导出备份 |

规则是"**能做的最小集**"：网页端只是打卡入口，任何一次误操作都要能在 App 上改回来。

## 5. 界面上的几个刻意选择

| 现象 | 原因 |
|---|---|
| 基准字号 18px，任务名 22px，点击区 56×56 | 目标用户是老花眼；56px 是"手指点得准"的下限 |
| 跨午夜显示"**次日** 01:00" | 老人看 "01:00" 会以为是今天凌晨，而这药是**今晚睡前**吃。写错一天会真的吃错 |
| 一个勾只在"做了/没做"之间切换 | 三态循环（待办→完成→没做→待办）对老人是灾难：想取消却点成"没做"，界面上还看不出区别 |
| "没做"只能从备注菜单进 | 同上 |
| 全做完显示"今天都做完了"，不是"剩 0 件" | 后者读起来像在说别的 |
| 未打卡的圈是**虚线 + 淡勾影**，不是实线空圈 | 截图验证时发现的：三个纯白圆看着像"都做完了但勾没显示"，或干脆像装饰。虚线是"这里还空着、等你填"的通用语汇 |
| 首屏有"正在打开…" | 不能白屏。白屏在老人那里的解读是"手机坏了" |
| 规则解析失败的任务**显眼地报出来** | 静默少一条，用户会以为"我今天真的没事"，而实际是规则读不出来 |
| 401 立刻停下并说"让家里人重发链接" | 无限重试 = 一直转圈。这个页面上唯一的出路就是重新要链接 |
| 退避 30 秒封顶 | 沙箱休眠一整晚，不封顶的话早上打开得等半小时 |

## 7. 手工验证清单

自动化测试覆盖不到"真实浏览器 + 真实老人"。下面这些**必须手点一遍**：

| # | 场景 | 期望 |
|---|---|---|
| 1 | 微信内置浏览器打开链接 | 不白屏、不弹"非官方网页"提示 |
| 2 | 同一浏览器先后打开两个成员的链接 | 后一个生效，前一个的 Cookie 被替换（不是两个都错） |
| 3 | 系统切深色模式 | 背景和文字都跟着变，不出现黑底黑字 |
| 4 | 链接作废后再点 | 一句话说清"让家里人重发"，**不是**一直转圈 |
| 5 | 飞行模式打开 | 说"手机好像没联网"，提到 Wi-Fi |
| 6 | 恢复网络 | 自动恢复，不用手动刷新 |
| 7 | 页面放着跨过午夜 | 自动提示"新的一天了"并刷新 |
| 8 | 服务端故意超时 | 8 秒后给出人话 + 一个"重试"按钮 |
| 9 | 任务名超长 / 成员名超长 | 不撑破布局，不出现横向滚动条 |
| 10 | 打卡后立刻看 App | 几秒内可见（走 `/sync` 拉取） |

前 6 条是"用户会遇到的真实故障"，7–10 是"布局和时序上容易漏的边界"。

## 8. 已知限制

- **没有 Service Worker**。离线时只能看到错误提示，看不到昨天的清单。
  加 PWA 会引入一套缓存失效逻辑，而"看到上一次的旧数据"在这个场景里比"看到连不上"更危险 ——
  老人会照着旧清单吃药。
- **不做 SPA fallback**。这个页面没有客户端路由，`/m/anything` 一律回到静态层，
  没有就 404。为将来可能的客户端路由预留 fallback，等于把"打错地址"的 404 变成 200。
- **备注只能写文字**。照片在 App 上只存本地，网页端拿不到，也不上传。
- **网页端不能"取消打卡"**，只能改成"没做"。这不是偷懒，是服务端本来就没有
  "取消"这个状态：`VALID_STATES` 只有 `done`/`makeup`/`skipped`，而
  `mergeCheckinState` 在 incoming 为 `null` 时**保留 existing**。
  也就是说前端发个 `null` 过去，"取消"不会发生，屏幕却会乐观地清掉那个勾 ——
  看起来取消了，刷新一下又回来。这个坑在浏览器里点了一遍才发现：
  早期版本点一个已完成的勾，弹出的是**备注框**，注释写着"不提供取消"、
  代码却在做别的事。

  > **待决**：要不要给 App 和网页端都补上真正的"取消"。如果补，得先改
  > `mergeCheckinState` 的合并语义（`null` 是"取消"还是"没收到"，
  > 在同步场景里这两种意思会撞车），不是加一个枚举值那么简单。
