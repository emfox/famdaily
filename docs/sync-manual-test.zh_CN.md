# 同步真机验证清单（P3 第一阶段）

> 单元测试能证明"合并算得对、落库写得对"，**证明不了"两台真手机连起来能用"**。
> 这份清单是那段空隙的填充物。每条都写了「怎么判失败」，因为最难查的
> 不是"报错"，是"看起来成功了但数据不对"。

## 0. 准备

### 0.1 起服务

```bash
cd server
FAMDAILY_PAIR_SECRET="$(openssl rand -hex 16)" \
FAMDAILY_DB="$PWD/data/famdaily.db" \
PORT=8787 node index.mjs
```

看到这一行才算起来：

```
[famdaily-sync] listening on :8787, db=/.../server/data/famdaily.db, families=0
```

**`db=` 后面必须是绝对路径。** 是相对路径就先停下来改——它在沙箱换工作
目录时会把库丢到临时目录。

```bash
curl -s localhost:8787/health
# {"ok":true,"families":0,"cursor":0,"pairEnabled":true}
```

`pairEnabled:false` = 口令没读到，第一台手机会加不进来。

### 0.2 造一个家庭与同步码

```bash
curl -s -X POST localhost:8787/pair/new \
  -H "X-Pair-Secret: $FAMDAILY_PAIR_SECRET" \
  -H 'Content-Type: application/json' -d '{"familyName":"我们家"}'
# {"code":"FAM-XXXX-XXXX-XXXX","expiresAtMs":...}
```

**码 10 分钟过期，且用一次就废。** 两台手机要两个码，各发一次。

### 0.3 手机上的准备

| 项 | 要求 |
|---|---|
| 网络 | 手机和服务在同一网络；服务地址填 `http://<电脑IP>:8787` |
| Android | release 包**必须**有 `INTERNET` 权限（已加，见 `AndroidManifest.xml`） |
| iOS | 只开了 `NSAllowsLocalNetworking`，所以 `http://` 局域网可用、公网 `http` 不行 |
| App | 至少各建一个成员，好区分"谁是谁的手机" |

> Android release 包缺 `INTERNET` 的表现是：请求瞬间失败、**不弹任何系统提示**。
> 这是第一个要排除的原因——不是同步代码的问题。

## 1. 配对

| # | 操作 | 期望 | 判失败的样子 |
|---|---|---|---|
| 1.1 | A 机：设置 → 多台手机同步 → 输入同步码 | 左侧标题是「还没开启同步」，右侧**没有任何字** | 右侧出现「未同步」→ 新用户会被吓一跳，见 `shortLabel` 的注释 |
| 1.2 | 填地址后点「下一步」 | 出现「这个家里有：」+ 成员名 | 直接跳到确认 → 预览被跳过了，用户没法判断输对没有 |
| 1.3 | 成员名看对了点确认 | 回到同步页，状态变「已经是最新的」或「正在同步…」 | 卡在「连接中…」超过 15 秒 → 看服务端有没有收到请求 |
| 1.4 | B 机用**同一个码**再配一次 | 报「同步码不对，或者已经用过了」 | 能配上 → 码没作废，是安全问题 |
| 1.5 | 输 `fam-xxxx-xxxx-xxxx`（小写、带前缀） | 一样能配上 | 报格式错 → 规范化没做 |
| 1.6 | 输 `123`（太短） | 立刻报「12 个字符」，**不发请求** | 转圈后才报错 → 本地没拦 |

## 2. 数据能不能对上（这一节最重要）

每条都在两台手机上都看一眼，**只看一台等于没测**。

| # | 操作 | A 机 | B 机期望 | 判失败的样子 |
|---|---|---|---|---|
| 2.1 | A 新增一个成员「爷爷」 | 立刻有 | 30 秒内自动出现（或回前台） | 永远不出现 → 推没出去，或拉的水位卡住 |
| 2.2 | A 建一个项目「吃降压药」，每天 8:00 | 有 | 有，**并且到 8:00 真的响** | 列表里有但不响 → 远端写入后没重排（`onDataChanged` 没接上） |
| 2.3 | A 打卡一次 | 变绿 | 变绿，时间一致 | 状态不一致 → 打卡合并规则错了 |
| 2.4 | B 补卡昨天的 | B 有 | A 有，且标成「补卡」不是「已完成」 | A 显示"已完成" → 合并时 state 被覆盖了 |
| 2.5 | A 改成员名「爷爷」→「外公」 | 改了 | 改了 | 只改一台 → LWW 判定或 `updated_at_ms` 没带 |
| 2.6 | A 删掉「外公」 | 没了 | 没了 | B 还在 → 墓碑没下来，或 `deleted_at_ms` 没同步 |
| 2.7 | A 删、B 同时改名（两台都断网操作，再联上） | 以**晚**的那次为准 | 两台一致 | 一台显示存在一台显示删除 → 合并规则两端不一致 |

### 2.x 已知会被判成"失败"但其实正确的行为

| 现象 | 为什么是对的 |
|---|---|
| A 撤销打卡（点成"未记录"），B 上还留着 | 客户端推的是全量当前状态，"我没有这条"没法表达"我删了"。撤销要靠服务端按 `updated_at_ms` 判墓碑。**方向是"多留一条"，不是"丢一条"** |
| 两台各建一个成员，顺序不一样 | `sortOrder` 各端独立编号，不重新对齐（对齐会把用户自己拖的顺序冲掉） |
| 照片在另一端看不到 | 设计如此：照片只存本机 |

## 3. 断网与休眠（沙箱的日常）

| # | 操作 | 期望 | 判失败的样子 |
|---|---|---|---|
| 3.1 | 停掉服务，A 打卡 | **照常打得动、不弹任何窗** | 出现错误弹窗 / 卡住 → 同步阻塞了主流程，这是最严重的一类 |
| 3.2 | 设置页看那一行 | 红字「网络不通」 | 什么都没有 → 用户以为自己配上了 |
| 3.3 | 重新起服务，等 30 秒 | 自动变「刚刚同步」 | 一直红着 → 退避没走，或第一次退避时间算错 |
| 3.4 | 连点 5 次「再试」 | 最多一个请求在飞 | 服务端日志刷屏 → 并发没复用 in-flight |
| 3.5 | 改 token（服务端 `pair/rotate`）后同步 | 红字「同步码已失效」，**不再自动重试** | 一直重试 → 401 被当成网络错误，会把限流打满 |
| 3.6 | 杀掉 App 再打开 | 30 秒内自己同步一次 | 要手动点 → 冷启动触发点没接上 |
| 3.7 | App 切后台再回前台（间隔 <30s） | **不发请求** | 每次都发 → 切来切去会在服务端日志里刷屏 |

## 4. 数据量

| # | 操作 | 期望 |
|---|---|---|
| 4.1 | A 一次性建 10 个项目，等同步完 | B 上 10 个都在（**不是 0 个、不是 9 个**） |
| 4.2 | A 连续快速打卡 20 次（不同项目） | B 上 20 条都在，没有一条重复 |
| 4.3 | A 建一个"连续 7 天"的疗程项目 | B 上显示「第 N/7 天」，不是「第 N/未知」 |

> 4.1 判 0 个是"整批共用一个 `server_at_ms`"的经典症状；
> 4.3 是 `course_total_days` 没落库的症状（这一条被本轮测试逮到过）。

## 6. 出问题时的第一手信息

| 想知道 | 查哪里 |
|---|---|
| 服务端收到了什么 | 服务端 stdout（每次 `/sync` 一行） |
| 客户端为什么没推 | `flutter run` 的 `[sync] ...` 那几行（`reason` 会写清是 `appLaunch`/`foreground`/`localChange`/`retry`） |
| 水位卡在哪 | `sqlite3 famdaily.db "select key,value from settings where key like 'sync.%'"` |
| 服务端认了几台设备 | `curl /health` 里的 `families` |

最后一步永远是：**把服务端的 `family.db` 拷出来，和手机上的库对着看**。
"两边不一致"这类问题，眼睛看数据库比看代码快一个数量级。
